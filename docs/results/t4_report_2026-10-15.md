## NVBench sweep

All 15 workload configurations produced batched GPU timings. Eight matrix cases used dimensions 64 and 128; three reduction cases used 4,096 to 1,048,576 inputs; four softmax cases used 64/257 rows and 128/513 columns.

| Operation | Batched GPU time range |
|---|---:|
| Matrix multiplication | 7.116–20.261 µs |
| One-block reduction | 11.044–1591.157 µs |
| Row softmax | 3.358–8.204 µs |

**Measurement limitation:** Colab did not sustain NVBench's default 75% clock threshold for most cold measurements. Ten cases accepted zero cold samples, and one accepted only one sample; those cold estimates are unusable. Four softmax cold measurements completed but reported 7.39–11.60% GPU noise. Batched measurements completed for all 15 cases, but clocks were not locked and these numbers should be treated as exploratory shared-host results. The full warnings are retained, including the failed cold measurements. A process exit code of zero alone does not establish benchmark convergence.

See the [unaltered NVBench CSV](t4_nvbench_2026-10-15.csv) and [full NVBench output](t4_nvbench_2026-10-15.md). NVBench's “Pass: Batch” concerns measurement completion, not a separate numerical correctness test for each swept shape. The numerical checks above use distinct odd-shaped/random inputs.

## Reproduce

Check out the source commit above. On an NVIDIA T4 with the dependencies listed above:

```bash
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_CUDA_ARCHITECTURES=75 -DCUDA_BACKEND=ON -DENABLE_NVBENCH=ON
cmake --build build --parallel 2
ctest --test-dir build --output-on-failure
./build/cuda_benchmark
./build/nvbench_kernels --min-time 0.1 --batch-target-time 0.1 --timeout 5 \
  --json t4_nvbench.json --csv t4_nvbench.csv
```

## What to improve next

The one-block sum leaves most of the GPU idle and takes roughly 1.3 ms in the correctness harness at one million inputs. A two-pass, multi-block reduction with a reusable scratch buffer is the clearest optimization target. Matrix and softmax timings are useful baselines, but there is no cuBLAS/CUB/PyTorch comparison here and therefore no library-relative speedup claim. Larger shapes, broader numerical checks and controlled-clock measurements should precede stronger performance claims.
